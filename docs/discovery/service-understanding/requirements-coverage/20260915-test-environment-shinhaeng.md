# 스토리 테스트 환경

## 테스트 대상

- 서비스: `https://poc-hiand.bstage.in/`
- 테스트 범위: Track 00 기획서 전체의 웹 검증 가능 범위 파악 및 가능한 팬 웹 흐름 실행
- 결제: 결제수단과 테스트 결제 가능 여부를 확인하기 전까지 실행하지 않는다.

## 계정 운영 원칙

- 테스트 계정: 제공받은 개인 계정을 사용한다.
- 공유 문서에는 계정 식별자와 비밀번호를 넣지 않는다.
- 사용자가 제공한 전체 접근정보는 요청에 따라 `test-access.local.md`에만 기록했으며 해당 파일은 `.gitignore`로 Git에서 제외한다. Git 제외는 파일 암호화나 로컬 접근 제한을 의미하지 않는다.
- 서비스 로그인과 라운지 가입 등 상태를 바꾸는 행동은 결과와 시각만 기록한다.
- 결제·주문·회원 탈퇴·프로필 공개 변경은 별도 지시가 있을 때만 실행한다.

## 첫 번째 Story

1. 서비스에 접속하고 제공된 테스트 계정으로 로그인한다.
2. 라운지 목록에서 아티스트를 선택한다.
3. 라운지의 스토리·콘텐츠·커뮤니티를 읽는다.
4. 라운지 가입 전후로 작성·반응·알림 설정 권한이 어떻게 달라지는지 확인한다.
5. 테스트 결과는 계정 정보나 개인정보 없이 별도 Story 기록 문서에 남긴다.

## 사전 접속 확인

- 제공된 공용 접근 비밀번호로 접속 게이트를 통과해 서비스 홈을 확인했다.
- 2026-09-14 최초 입력은 이메일 형식 검사에서 막혔으나 사용자가 주소를 확인한 후 로그인에 성공했다. 로컬 접근정보의 이메일도 확인된 주소로 수정했다.
- 공개 라운지·콘텐츠·커뮤니티·상품·공지·FAQ·이벤트 및 비로그인 제한을 실제 확인했다. [실행 기록](./20260915-poc-web-test-log-shinhaeng.md)과 [전체 요구사항 검증표](./20260915-requirement-coverage-shinhaeng.md)를 참고한다.
- 회원 상태에서 무료 라운지 입장·편집기·알림/스케줄·보유 이용권/주문·유형별 주문서를 확인했다. 라운지는 후속 테스트용으로 가입 상태를 유지한다.
- 이번에 추가한 장바구니 항목과 하트 반응은 제거해 복구했다. 프로필·알림 수신 설정·기존 스타/이용권은 변경하지 않았다.
- 결제, 주문 확정, 탈퇴, 프로필 저장은 실행하지 않았다. 주문서 열람 과정의 임시 체크아웃은 확정 주문과 구분한다.
