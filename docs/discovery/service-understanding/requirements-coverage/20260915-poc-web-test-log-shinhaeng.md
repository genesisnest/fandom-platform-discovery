# Track 00 — POC 웹 스토리 테스트 기록

## 결론과 실행 범위

2026-09-14, 사용자가 열어 둔 Chrome에서 `https://poc-hiand.bstage.in/`의 실제 화면을 탐색했다. 1차 비로그인 24개와 주소 확인 후 2차 회원 28개, 총 52개 확인 항목을 기록했다. **테스트 계정 로그인과 무료 라운지 입장에 성공했다.** 회원 메뉴·기존 이용권/주문·게시글/댓글 편집기·리액션 등록/취소·알림·스케줄·장바구니·상품 유형별 주문서를 확인했다. 모든 요구사항의 합격이나 앱/운영 기능 검증 완료를 의미하지 않는다.

- 원본: [01. 요구사항_v1.00.xlsx](./01.%20요구사항_v1.00.xlsx), 초기 해석: [기획서 분석](./20260915-requirements-analysis-shinhaeng.md).
- 전체 검토 목록: [요구사항별 웹 검증 범위](./20260915-requirement-coverage-shinhaeng.md). 기능·정책 335행, 비기능 16행, 참고 알림 8행을 각각 연결했다.
- 실제 웹에서 확인한 제한과 기획의 목표 정책을 구분한다. POC에서 못 찾은 기능을 플랫폼 전체의 미구현으로 단정하지 않는다.
- 데스크톱 Chrome, 한국 시간대. 언어 한국어·통화 KRW를 확인했다. 언어·통화·게시판 보기 방식의 임시 변경은 복구했다.
- 개발 서버, 모바일 앱, WebView, 아티스트 앱, 어드민 화면 테스트는 실행하지 않았다.
- 결제·주문 확정·최종 약관 동의·회원가입·탈퇴·인증정보 변경·공개 게시물/댓글 작성·파일 업로드는 실행하지 않았다. 결제수단은 일부 상품의 표시만 확인했으며 실제 결제 승인/테스트 수단은 미확인이다.
- 테스트로 담은 장바구니 항목과 하트 반응은 제거해 원상복구했다. 무료 가입한 김배우 라운지는 후속 테스트용으로 유지한다. 기존 프로필·DM 아티스트/이용권·포인트·알림 수신 설정은 변경하지 않았다. 조회 과정에서 읽음 상태·조회수 등 서비스의 자동 변화는 발생할 수 있다.
- 계정 식별자·비밀번호는 이 보고서에 넣지 않는다. 기존 로컬 접근정보 파일만 Git 제외 상태로 유지한다.

## 2차 — 계정 주소 확인 후 회원 테스트

사용자가 계정 도메인 끝부분을 확인한 뒤 로그인했다. 개인 이름·이메일·주문번호·체크아웃 식별자는 공유 문서에 전사하지 않는다. 기존 이용권/0원 주문은 계정에 있던 데이터의 조회 결과이며 이번 테스트에서 구매한 것이 아니다.

| ID | 스토리·행동 | 실제 결과와 남은 조건 |
| --- | --- | --- |
| W-25 | 확인된 주소로 로그인→My | 로그인 성공 후 프로필·계정 이메일, 내 이용권/티켓 1개·포인트 0P와 회원 메뉴가 표시됐다. 기존 주소 형식 오류는 해소됐다. 스티커·하이페이·쿠폰·화면 설정·통합 ID QR의 전용 진입점은 찾지 못했다. |

## 기획과 비교할 발견 사항

### 재현된 POC 상태·데이터 문제

- LINE-UP 일부가 운영 서비스로 연결되고 홈/샵 배너 일부는 `http://sample.c`다. 테스트 환경 안에서 이어지는 사용자 흐름이 끊길 수 있다. 외부 링크 자체가 금지인지와 별개로 POC 테스트 링크 정비가 필요하다.
- `parkseojun` 라운지가 김배우로 보이며 PARK SEO JUN 상품 필터에 HAN SO HEE 상품이 나타난다. fixture 의도인지 상품/라운지 매핑 오류인지 운영 설정 확인이 필요하다.
- 멤버십 소개 링크는 모두 같은 상품으로 향한다. 여러 멤버십 소개가 의도된 배너라면 링크 설정을 확인해야 한다.
- FAQ에 테스트 문자열, 약관에 사업자명·서비스명·시행일 작성 안내가 남아 있다. 특히 현재 약관 본문을 목표 결제·환불 정책의 확정 근거로 사용하면 안 된다. 법률 적정성을 평가한 결과는 아니다.
- 이벤트가 없어 상세·응모·당첨 검증이 불가능하다. 현장수령 회차는 과거 일정 데이터이므로 현재 운영 흐름을 대표하지 않을 수 있다.

### 확정 결함이 아닌 기획·플랫폼 확인 사항

- 앱 하단 탭과 공개 브라우저 상단 메뉴는 다른 플랫폼이다. 웹에서 공개 읽기가 가능한 것을 앱 로그인 게이트 요구 위반으로 처리하지 않는다.
- 기획은 라운지 4개 탭·캘린더·검색을 적지만 대상 POC 라운지는 3개 탭과 다른 헤더를 사용한다. 웹/앱 적용 범위와 탭 ON/OFF 설정을 확인해야 한다.
- 언어는 웹 7개와 기획 6개가 다르다. 베트남어 유지 여부와 플랫폼별 범위를 결정해야 한다.
- 샵은 아티스트/카테고리 중심이며 기획의 상품 유형 탭·사이드 메뉴·웹 버전 표시 전체와 일치하지 않는다. 기존 화면 유지/개편 범위를 확인해야 한다.
- DM의 기간형·12개월·다인권 판매가 현재 공존한다. TO-BE의 웹 아티스트 구독형·앱 슬롯형·24개월 연장 상한과 동일하게 구현됐다고 볼 수 없다.
- 비공개 보드와 멤버십 전용 본문 제한은 관찰했지만, 권한 모델의 모든 조합과 그룹 N:N 관계는 확인되지 않았다.

## 남은 검증 조건

1. 회원 로그인 대기는 해소됐다. 스티커·테마·QR·쿠폰·하이페이·이벤트 내역·내 VOD 등 찾지 못한 경로는 웹/앱 적용 범위와 실제 진입점을 확인한다.
2. 공개 게시글/댓글 발행·파일 업로드·프로필 저장·회원 차단·라운지 나가기/재가입·알림 토글 변경은 이번에 실행하지 않았다. 실제 상태 변경 테스트를 이어갈 경우 대상·발행 내용·파일과 복구 범위를 정하고 필요한 사용자 확인을 받은 뒤 실행한다.
3. 일반·해당 아티스트 DM·멤버십·둘 다 보유한 계정 조건과 테스트 콘텐츠를 마련해 멤버십/DM/OR/AND 접근을 비교한다. 현재 계정의 다른 아티스트 이용권 1개와 라운지 가입만으로 전체 ACL을 검증할 수 없다. 이벤트·리워드·현장수령 주문·구매 VOD/배송 데이터도 필요하다.
4. 상품 유형별 단일 주문서는 확인했다. 복합 주문·실제 주소/배송비·모든 통화/PG·쿠폰/포인트·기간 연장·환불/갱신은 미검증이다. 테스트 결제수단·허용 상품·금액 한도·정기결제 허용 여부가 정해지기 전에는 최종 동의·주문·결제를 하지 않는다.
5. 앱·아티스트·어드민·예약 실행·비기능 항목은 별도 환경/권한/데이터/측정 기준을 준비한 뒤 검증한다.

화면 증거는 테스트 당시 DOM·접근성 상태·일부 스크린샷 관찰을 위 표에 전사했다. 스크린샷 파일이나 네트워크/서버 로그를 별도 보관한 것은 아니며, 속도·트래픽·보안 내부 구현을 검증했다고 주장하지 않는다.
