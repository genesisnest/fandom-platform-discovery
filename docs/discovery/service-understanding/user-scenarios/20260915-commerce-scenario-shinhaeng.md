# 상품·주문·결제 도메인 Story 조사 리포트

## 1. 조사 개요

- 조사일: 2026-09-15
- 대상: POC 데스크톱 팬 웹
- 목적: 상품 탐색부터 구매 이후까지의 기능과 도메인 규칙을 이해한다.
- 방법: 기획서 요구사항과 테스트 계정으로 확인한 POC 화면을 대조했다.
- 안전 범위: 상품 선택·장바구니·주문서까지만 진행했다. 최종 결제, 주문 확정, 환불 신청, 개인정보 저장은 실행하지 않았다.

상세 테스트 이력은 [Track 00 웹 테스트 리포트](../requirements-coverage/20260915-poc-web-test-log-shinhaeng.md), 기획서 행별 범위는 [원본 요구사항별 검증 범위](../requirements-coverage/20260915-requirement-coverage-shinhaeng.md)를 함께 참고한다. 계정정보와 개인 주문 식별자는 이 문서에 기록하지 않는다.

## 2. 전체 구매 흐름

```text
SHOP / DM / MEMBERSHIP
  └─ 상품 목록
      └─ 상품 상세
          └─ 유형별 옵션 선택
              ├─ 장바구니 ─ 수량·합계·삭제
              └─ 바로 구매
                  └─ 유형별 주문서
                      ├─ 주문자·수령/회원 정보
                      ├─ 상품·할인·포인트·결제수단
                      ├─ 약관 동의
                      └─ 결제하기 [이번 조사에서는 미실행]
                          └─ 주문/결제 내역
                              └─ 상세·고객센터·취소/환불 정책
```

핵심은 **하나의 공통 구매 골격에 상품 유형별 옵션과 주문정보가 붙는 구조**다. 배송 상품은 배송지, 현장수령 상품은 행사 회차·장소, 멤버십은 회원정보, DM 이용권은 스타·기간 정보가 주문서에 추가된다.

## 3. 영역별 조사 결과 요약

| 영역 | POC에서 확인한 기능 | 판정 |
| --- | --- | --- |
| 상품과 옵션 | 배송·현장수령·멤버십·DM 기간형/구독형·회원 전용·품절 상품 구분, 단계형 옵션, 구매 수량 제한 | 부분 확인 |
| 장바구니와 주문서 | 담기, 수량·합계, 삭제, 유형별 주문서 분기, 포인트·약관·결제 진입 | 확인 / 결제 미실행 |
| 결제수단과 하이페이 | 유상 멤버십·DM 주문서에서 `간편결제/신용카드`, `액심베이` 노출 | 일부 확인 / 하이페이 미노출 |
| 배송과 현장수령 | 국내·해외 배송지 폼 전환, 현장 회차·일시·장소 표시, 현장수령 주문서의 배송지 미노출 | 부분 확인 |
| DM 이용권과 멤버십 | 기간·인원·스타 선택, 사용/구매확정 고지, 멤버십 기간·혜택·필수정보 | 부분 확인 |
| 할인·쿠폰·환불 | DM 상품의 정상가/할인가, 구매확정 시점, 고객센터 경로 | 일부 확인 / 쿠폰·환불 실행 불가 |

`부분 확인`은 팬 웹에서 화면과 진입 흐름은 확인했지만, 결제 데이터·보유 자격·어드민 설정 또는 시간 경과가 필요한 정책은 확정하지 못했다는 뜻이다.

## 4. 상품과 옵션

### Story A. 상품 유형을 구분해 탐색한다

SHOP과 DM 이용권 목록에서 다음 유형을 확인했다.

- 일반 배송 상품
- 현장수령 상품
- 멤버십 상품과 멤버십 회원 전용 상품
- DM 기간형 이용권과 구독형 이용권
- 온라인 상품, 품절 상품
- 무료·유료·할인 상품

상품 상세는 공통적으로 상품명·가격·설명·구매 진입점을 제공하지만, 옵션은 유형에 맞게 달라진다.

| 상품 유형 | 확인한 옵션·제약 |
| --- | --- |
| 일반 배송 | 색상 → 사이즈 → 수량의 단계형 선택. 예시 상품은 1회 최대 21개, 1인 최대 35개를 안내했고 22 입력 시 21로 제한됐다. |
| 현장수령 | 수령 회차 → 수량 선택. 회차별 일시와 부스 위치가 함께 표시됐다. 지난 회차로 보이는 항목은 흐리게 표시됐다. |
| DM 기간형 | 기간·이용 인원·스타를 표시한다. 일부 상품은 스타 변경 불가, 결제당 1개, 이미 구매한 동일 스타 재구매 불가를 안내한다. |
| 멤버십 | 등급·기간·혜택을 표시한다. 조사 대상은 단일 옵션, 12개월 상품이었으며 가입 시 별도 필수정보를 요구했다. |
| 멤버십 전용 상품 | 비보유 계정의 구매 진입을 안내 팝업으로 차단했다. |

단일 유형의 최적화 화면은 확인했다. 세트·믹스처럼 여러 유형을 한 상품에 조합한 복합 옵션은 테스트 데이터가 없어 확인하지 못했다.

## 5. 장바구니와 주문서

### Story B. 선택한 상품을 장바구니에서 관리한다

현장수령 상품으로 다음 흐름을 확인했다.

1. 옵션과 수량을 선택해 장바구니에 담는다.
2. 장바구니에서 상품, 수량, 합계를 확인한다.
3. 항목을 삭제하면 빈 상태로 돌아간다.

서로 다른 배송 방식이나 여러 판매자의 상품을 함께 담는 복합 장바구니는 확인하지 못했다. 조사 종료 시 장바구니는 빈 상태로 복구했다.

### Story C. 상품 유형에 맞는 주문서를 작성한다

| 주문서 유형 | 공통 정보 | 유형별 추가 정보 |
| --- | --- | --- |
| 일반 배송 | 주문자, 상품, 포인트, 결제·약관 영역 | 배송지 등록, 국내/해외 주소 |
| 현장수령 | 주문자, 상품, 포인트, 결제수단, 약관 | 행사명, 회차, 일시, 장소. 배송지는 보이지 않음 |
| 멤버십 | 주문자, 상품, 포인트, 결제수단, 약관 | 이름, 생년월일, 국가번호 포함 전화번호, 구매 후 수정 불가 안내 |
| DM 기간형 | 주문자, 상품, 선택 스타, 기간, 결제수단, 약관 | 배송지·멤버십 정보 없음 |

기획서의 공통 주문서에는 최근 주문정보 불러오기, 쿠폰, 할인·배송비 상세, 미성년자 법정대리인 동의도 포함된다. 현재 확인한 POC 주문서에서는 이 항목 전체를 검증할 데이터나 진입점이 없었다.

## 6. 결제수단과 하이페이

### Story D. 유상 상품의 결제수단을 선택한다

유상 멤버십과 할인된 DM 이용권 주문서에서 다음 결제수단이 나타났다.

- 간편결제/신용카드
- 액심베이

포인트 영역과 `최대 사용`도 있었지만 계정 잔액이 0P여서 실제 적용은 확인하지 못했다. 무료 상품에서는 결제수단 영역이 생략될 수 있었다.

기획서에는 상품·통화·플랫폼에 따라 Toss Payments, PayPal, Eximbay, Stripe, Konbini, Apple·Google 인앱결제 등이 정의돼 있다. 이번 POC 조건에서 보인 두 항목만 실제 웹 근거로 본다.

### Story E. 하이페이를 등록하고 관리한다

기획서상 하이페이는 다음 개념을 가진 별도 간편결제 수단이다.

- 결제수단 등록·관리와 6자리 비밀번호
- 백업 결제수단
- 한 계정의 대표 결제수단 정책
- 허용 PG 범위

그러나 My 메뉴와 확인한 주문서 어디에서도 `하이페이` 진입점이나 명칭을 찾지 못했다. 따라서 현재 팬 웹 POC에 미구현·미노출인지, 특정 국가·계정·앱에서만 제공되는지는 추가 확인이 필요하다.

## 7. 배송과 현장수령

### Story F. 배송지를 국가에 맞게 입력한다

배송 주문서에서 국가를 대한민국에서 일본으로 바꾸면 다음 해외 주소 필드가 나타났다.

- 영문 이름·성
- 국가번호가 적용된 전화번호
- 주소, 도시, 도·현, 우편번호

국가별 폼 전환은 확인했지만 주소 저장, 우편번호 기반 배송비 계산, 통관비, 실제 배송, 송장 조회는 실행하지 않았다. 기획서의 해외배송 7~15영업일 안내도 해당 테스트 상품 화면에서는 확인하지 못했다.

### Story G. 행사장에서 상품을 수령한다

현장수령 상품은 배송 대신 회차·수량을 선택하고, 주문서에 행사명·회차·일시·장소를 표시한다. 상품 상세에도 배송 상품이 아니며 행사장에서 수령한다는 안내가 있었다.

수령 완료까지는 주문 확정 후 생성되는 수령 QR, 현장 검증 계정과 실제 행사 운영 데이터가 필요하다. 이번 조사에서는 주문서까지만 확인했다.

## 8. DM 이용권과 멤버십 상품

### Story H. DM 기간형 이용권을 구매한다

목록에서 1·3·6·12개월, 1인·다인, 기간형·구독형 상품과 여러 가격을 확인했다. 3개월 할인 상품은 정상가와 판매가를 함께 표시했고 주문서 합계에는 판매가가 적용됐다.

기간형 이용권의 주요 고지는 다음과 같다.

- 최초 POP 입장 시 사용이 시작된다.
- 사용하거나 결제 후 7일이 지나면 구매확정되어 청약철회가 제한된다.
- 다인권은 선택한 스타 중 최초 입장을 기준으로 사용이 시작된다.
- 일부 멤버십 전용 상품은 이용권 결제 시 미확정 멤버십도 구매확정될 수 있다.

구독형은 두 번째 결제부터 결제일에 즉시 구매확정되어 철회가 제한된다는 안내가 있었다. 자동갱신, 갱신 실패 재시도, 해지, 24개월 연장 상한은 실제 구독과 시간 경과가 필요해 확인하지 못했다.

### Story I. 멤버십에 가입한다

멤버십 상세에서 기간·가격과 다음 혜택을 확인했다.

- 멤버십 전용 콘텐츠와 설문
- 스타 스토리 열람·댓글
- 멤버십 커뮤니티
- 멤버십 전용 상품

주문서 진입 시 이름·생년월일·전화번호를 필수로 수집하며 구매 후 수정 불가를 안내했다. 콘텐츠를 이용하거나 결제 후 7일이 지나면 구매확정된다는 고지도 있었다. 가입 완료, 멤버십 카드·코드, 권한 부여, 갱신은 결제하지 않아 검증하지 않았다.

## 9. 할인·쿠폰·환불

### Story J. 할인 가격을 확인한다

DM 3개월 상품에서 정상가 14,700원과 판매가 13,200원이 함께 표시됐고, 주문서의 상품 금액과 결제 예정 금액에는 13,200원이 적용됐다. 별도 `할인 금액` 행은 보이지 않았다.

기획서의 그룹 구독 할인, 쿠폰과 중복 적용, 중도 환불 시 할인분 회수는 조건이 갖춰진 상품·구독 계정이 없어 확인하지 못했다.

### Story K. 쿠폰을 조회하고 적용한다

기획서에는 보유/받기 탭, 쿠폰 수량·필터·정렬, 빈 상태, 적용 안내가 정의돼 있다. 현재 My 메뉴와 확인한 주문서에는 쿠폰 메뉴나 적용 영역이 보이지 않았다.

이 결과는 `쿠폰 기능이 없다`는 뜻이 아니라, 현재 POC·계정·상품 조건에서는 팬 웹 진입점을 찾지 못했다는 뜻이다.

### Story L. 주문을 취소하거나 환불을 요청한다

- My의 주문/결제 내역은 실물상품·멤버십·이용권·티켓으로 구분되고, `전체`와 `결제취소/부분취소` 필터가 있다.
- 기존 이용권 주문 상세에는 상태·기간·금액·선택 스타·결제정보와 고객센터 버튼이 보였다.
- 해당 상세에서 직접 취소·환불 버튼은 찾지 못했다.
- 고객센터에는 `취소/교환/환불` FAQ 분류가 있지만 현재 등록된 FAQ가 없고 `직접 문의하기`를 제공한다.

따라서 현재 관찰된 환불 경로는 셀프 처리보다 고객센터 문의 중심이다. 실제 취소 가능 기간, 구매확정 전후 분기, 부분취소 금액, 국내 일할 계산과 위약금, 해외 이용권 환불 제한은 거래를 만들지 않아 검증하지 않았다.

## 10. 기획과 POC 사이에서 확인이 필요한 지점

| 확인 과제 | 이유 | 필요한 조건 |
| --- | --- | --- |
| 하이페이 노출 조건 | 기획에는 상세 정책이 있으나 팬 웹에서 진입점 미확인 | 지원 국가·통화·계정 또는 앱 환경 |
| 쿠폰 조회·적용 | My와 주문서에서 영역 미확인 | 쿠폰 발급 계정과 적용 대상 상품 |
| 그룹 할인 | 구독 아티스트 수에 따른 할인 규칙 미검증 | 동일 그룹 복수 구독 상품·계정 |
| 결제수단 전체 매핑 | 현재 두 종류만 노출 | 국가·통화·상품·플랫폼별 테스트 조합 |
| 배송비·송장·통관 | 주소 입력과 주문 이후 단계 미실행 | 테스트 주소, 결제 가능한 배송 주문 |
| 현장수령 QR | 보유 주문이 없음 | 확정된 현장수령 주문과 운영 검증 화면 |
| DM 자동갱신·연장 | 시간·기존 구독이 필요 | 구독형 테스트 주문, 갱신/실패 시나리오 |
| 취소·환불 계산 | 실제 거래와 상태 전이가 필요 | 환불 가능한 테스트 결제와 CS 처리 권한 |

## 11. 결론

플랫폼의 커머스는 **상품 유형별 옵션 → 공통 주문서의 유형별 확장 → 주문내역과 고객센터**로 이어진다. 팬 웹에서는 상품 탐색, 옵션 제한, 장바구니, 국내·해외 배송지, 현장수령 정보, DM·멤버십 구매조건과 일부 결제수단까지 확인할 수 있었다.

반면 하이페이, 쿠폰, 그룹 할인, 실제 배송·현장수령, 자동갱신, 취소·환불 계산은 현재 계정과 비결제 테스트만으로 기능 존재나 정책 집행을 확정할 수 없다. 다음 조사는 새 화면을 넓게 탐색하기보다 위 표의 테스트 데이터와 권한을 먼저 준비하는 편이 효율적이다.

조사 종료 시 최종 결제나 새 주문은 생성하지 않았고, 장바구니는 빈 상태였다.
